# Agent instructions: module-docs-sphinx

This module adds Sphinx documentation rules to a project built on
the `stack-fastapi-vuetify` core template.

**Prerequisite**: `stack-fastapi-vuetify/.ai/instructions.md` must
already be loaded and followed.

---

## Directory layout

```
docs/
  conf.py
  index.rst
  user/
    index.rst          end-user guides and how-tos
  developer/
    index.rst
    architecture.md    (or .rst — both are acceptable)
    code-style.md
    invariants.md
    security.md
    api/
      index.rst        autodoc pages for backend modules
  operator/
    index.rst          deployment, configuration, runbooks
  _static/
  _templates/
.readthedocs.yaml      at the repository root
```

The `docs/` directory is always at the repository root. Do not
place it inside `backend/` or `frontend/`.

The three-section split is mandatory:

| Section | Audience | Contents |
|---|---|---|
| `user/` | End users | Features, how-tos, tutorials |
| `developer/` | Engineers | Architecture, API reference, code guide |
| `operator/` | Ops / DevOps | Deployment, env vars, backups, runbooks |

Each section has its own `index.rst` that is included in the
root `index.rst` toctree. Add a section only when it has at
least one substantive page.

## Required extensions

```python
# docs/conf.py
extensions = [
    "sphinx.ext.autodoc",
    "sphinx.ext.autosectionlabel",
    "sphinx.ext.intersphinx",
    "sphinx_autodoc_typehints",
    "myst_parser",            # if .md files are used alongside .rst
]
```

- **autodoc** — pulls docstrings from Python source. All public
  modules, classes, and functions must have docstrings.
- **autosectionlabel** — enables cross-document section references
  without manual labels. Prefix is required to avoid collisions:
  `autosectionlabel_prefix_document = True`
- **intersphinx** — links to external library docs.
- **sphinx_autodoc_typehints** — renders type annotations from
  function signatures into the generated docs.
- **myst_parser** — permits MyST Markdown (`.md`) files to be
  included in the toctree. Use consistently: do not mix RST and
  Markdown syntax in the same file.

## Theme

```python
html_theme = "furo"
```

`furo` is the required theme. Do not use `sphinx_rtd_theme`,
`alabaster`, or any other theme without explicit approval recorded
in `contract.md`.

Install with:

```
uv add --dev sphinx furo sphinx-autodoc-typehints myst-parser
```

## Version sourcing

The project version must be read from `pyproject.toml`, not
hard-coded in `conf.py`:

```python
# docs/conf.py
import tomllib
from pathlib import Path

with open(Path(__file__).parent.parent / "pyproject.toml", "rb") as f:
    _meta = tomllib.load(f)

release = _meta["project"]["version"]
version = ".".join(release.split(".")[:2])
```

This ensures `conf.py` and `pyproject.toml` are always in sync. A
version mismatch is a build error, not a silent discrepancy.

## Docstring requirements

Docstrings are the canonical documentation for all public symbols.
RST pages generated by `autodoc` must not duplicate or paraphrase
docstring content — they include it via `.. automodule::` or
`.. autoclass::`.

Required docstring format (Google style, enforced by
`sphinx_autodoc_typehints`):

```python
def create_access_token(subject: str, settings: Settings) -> str:
    """
    Issue a short-lived access JWT.

    :param subject: User identifier (UUID as string).
    :param settings: Application configuration.
    :returns: Signed JWT string.
    :raises ValueError: If subject is empty.
    """
```

- Every public module, class, and function must have a docstring.
- Private symbols (prefixed `_`) do not require docstrings unless
  they are complex.
- Docstrings must be ≤ 79 characters per line.

---

## RST formatting rules

- Maximum line length for RST files: **80 characters**.
- Use 3-space indentation inside directives.
- Heading hierarchy (use consistently throughout the project):

  ```
  Page title — underline with ====
  Section    — underline with ----
  Subsection — underline with ~~~~
  ```

- No hard tabs in `.rst` or `.md` files.
- One blank line before and after directives.

---

## `autodoc` page conventions

```rst
.. automodule:: app.routers.auth
   :members:
   :undoc-members:
   :show-inheritance:
```

- One `automodule` directive per `.rst` file.
- Import all models in `app/models/__init__.py` so autodoc can
  resolve cross-references.
- Use `:show-inheritance:` for all class directives so the
  inheritance chain is visible.

## intersphinx mapping

```python
intersphinx_mapping = {
    "python": ("https://docs.python.org/3", None),
    "sqlalchemy": (
        "https://docs.sqlalchemy.org/en/20/",
        None,
    ),
    "fastapi": ("https://fastapi.tiangolo.com/", None),
    "pydantic": ("https://docs.pydantic.dev/latest/", None),
}
```

Add mappings incrementally as cross-references are needed. Do not
add mappings for libraries that are not referenced anywhere in the
docs.

## ReadTheDocs configuration

Place `.readthedocs.yaml` at the repository root:

```yaml
version: 2

build:
  os: ubuntu-lts
  tools:
    python: "latest"

sphinx:
  configuration: docs/conf.py

python:
  install:
    - method: pip
      path: backend
      extra_requirements:
        - docs
```

Add a `[project.optional-dependencies]` table to `pyproject.toml`:

```toml
[project.optional-dependencies]
docs = [
    "sphinx>=8",
    "furo",
    "sphinx-autodoc-typehints",
    "myst-parser",
]
```

The ReadTheDocs build installs the backend package (to resolve
imports for autodoc) plus the docs extras. It does not install
frontend tooling.

## Building locally

```
cd docs
make html
# or without make:
python -m sphinx . _build/html
```

The build must produce zero warnings. Treat warnings as errors
in CI:

```
sphinx-build -W -b html docs docs/_build/html
```

---

## Prohibited patterns

- Hard-coded version strings in `conf.py`.
- Duplicating docstring content in RST narrative pages.
- Using `sphinx_rtd_theme` without approval.
- `.rst` files with lines exceeding 80 characters.
- Committing `docs/_build/` — add it to `.gitignore`.
- Running `sphinx-build` without `-W` in CI.
