# Agent instructions: module-database-postgresql

This module adds PostgreSQL database rules to a project built on
the `stack-fastapi-vuetify` core template.

**Prerequisite**: `stack-fastapi-vuetify/.ai/instructions.md` must
already be loaded and followed.

---

## Architecture invariants

- **Alembic owns all schema changes.** `Base.metadata.create_all()`
  is unconditionally prohibited in application code. The ORM is for
  querying only; it never creates or alters tables.
- **One session per request.** The `get_db` generator yields exactly
  one `Session` (or `AsyncSession`) per request and closes it in a
  `finally` block. Sessions must not be stored as module-level
  globals or as instance attributes on long-lived objects.
- **`DATABASE_URL` comes from `pydantic-settings`.** It is never
  hard-coded. It is never read with a bare `os.environ.get()`
  without a fallback that would cause a loud startup failure.
- **Migrations are reviewed before commit.** Autogenerated
  revisions are a starting point, not a finished product.

---

## Configuration

```python
# app/config.py
class Settings(BaseSettings):
    DATABASE_URL: PostgresDsn

    model_config = SettingsConfigDict(
        env_file=".env",
        env_file_encoding="utf-8",
    )
```

`PostgresDsn` validates the URL at startup. A missing or malformed
URL causes a clear `ValidationError` rather than a cryptic runtime
failure.

## Driver: psycopg3

`psycopg` (version 3) is the required PostgreSQL driver. It
supports both synchronous and asynchronous operation in a single
package. Do not use `psycopg2`, `asyncpg`, or any other driver.

### DSN handling

The `DATABASE_URL` environment variable must be a standard
PostgreSQL DSN without any SQLAlchemy dialect modifier:

```
DATABASE_URL=postgresql://user:pass@localhost:5432/mydb
```

The `+psycopg` dialect modifier required by SQLAlchemy must be
**injected at runtime in Python**, never stored in the env var.
This keeps the connection string portable and provider-agnostic.

```python
# app/database.py
def _make_engine_url(raw_url: str) -> str:
    """
    Inject the psycopg dialect modifier into a standard DSN.

    :param raw_url: Plain postgresql:// DSN from the environment.
    :returns: URL with +psycopg modifier for SQLAlchemy.
    """
    return raw_url.replace(
        "postgresql://", "postgresql+psycopg://", 1
    )
```

The `_make_engine_url` helper is called when constructing the
engine, not at settings parse time.

## Session management

### Synchronous

```python
# app/database.py
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker, DeclarativeBase

engine = create_engine(
    _make_engine_url(str(settings.DATABASE_URL)),
    pool_pre_ping=True,
)
SessionLocal = sessionmaker(bind=engine)

class Base(DeclarativeBase):
    pass

def get_db():
    """
    Yield a database session for the duration of a request.

    Always closed in finally, whether or not an exception occurs.
    """
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

### Asynchronous

```python
# app/database.py
from sqlalchemy.ext.asyncio import (
    AsyncSession,
    async_sessionmaker,
    create_async_engine,
)
from sqlalchemy.orm import DeclarativeBase

engine = create_async_engine(
    _make_engine_url(str(settings.DATABASE_URL)),
    pool_pre_ping=True,
)
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)

class Base(DeclarativeBase):
    pass

async def get_db():
    """
    Yield an async database session for the duration of a request.

    Always closed in finally, whether or not an exception occurs.
    """
    async with AsyncSessionLocal() as session:
        try:
            yield session
        finally:
            await session.close()
```

Choose one mode (sync or async) per project. Document the choice
in `contract.md`. Do not mix sync and async SQLAlchemy in the
same application.

## Migrations with Alembic

### Initial setup

```
uv add alembic sqlalchemy "psycopg[binary]"
alembic init alembic
```

Edit `alembic/env.py`:

```python
from app.config import get_settings
from app.database import Base, _make_engine_url
# import all models so Alembic can detect them:
import app.models  # noqa: F401

settings = get_settings()
# Inject the +psycopg dialect modifier; DATABASE_URL env var
# stays as a plain postgresql:// DSN.
config.set_main_option(
    "sqlalchemy.url",
    _make_engine_url(str(settings.DATABASE_URL)),
)
target_metadata = Base.metadata
```

### Creating a migration

```
alembic revision --autogenerate -m "describe the change"
```

**Always review the generated file before committing.** Common
autogenerate blind spots:

- Column renames (detected as drop + add — data loss risk).
- Non-default index types (partial indexes, expression indexes).
- `server_default` values on existing columns.
- Changes inside PostgreSQL function bodies.

Annotate the migration file with a comment if manual adjustments
were required.

### Applying migrations

Deploy order is always:

```
alembic upgrade head
# then start the application process
```

This order must be encoded in the `docker-compose.yml` health
check or the container startup entrypoint. The application must
not start before the database is migrated.

### Rollback

Always write a working `downgrade()` function. Irreversible
migrations (e.g. data transformations) must include a comment
explaining the rollback strategy and must be flagged for manual
review in the PR.

## Model conventions

```python
import uuid
from datetime import datetime, timezone
from sqlalchemy import DateTime, func
from sqlalchemy.orm import Mapped, mapped_column
from app.database import Base

class TimestampMixin:
    """
    Adds created_at and updated_at columns to a model.
    """
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        nullable=False,
    )
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True),
        server_default=func.now(),
        onupdate=func.now(),
        nullable=False,
    )

class UUIDPrimaryKeyMixin:
    """
    Uses a UUID primary key instead of a serial integer.
    """
    id: Mapped[uuid.UUID] = mapped_column(
        primary_key=True,
        default=uuid.uuid4,
    )
```

- Always use timezone-aware `DateTime(timezone=True)` columns.
- Prefer UUID primary keys for user-facing resources.
- Integer serial primary keys are acceptable for internal lookup
  tables with no external exposure.

## PostgreSQL DDL documentation

PostgreSQL supports inline documentation via `COMMENT ON TABLE`
and `COMMENT ON COLUMN`. This documentation is stored in the
database itself and is visible to every tool that connects.

**Rule**: every table and every column whose purpose is not
immediately obvious from its name alone must have a one-line
`COMMENT`. Keep these short — one sentence maximum.

Add comments directly in Alembic migration files using
`op.execute`:

```python
def upgrade() -> None:
    op.create_table(
        "circle_memberships",
        sa.Column("id", sa.UUID, primary_key=True),
        sa.Column("circle_id", sa.UUID, nullable=False),
        sa.Column("user_id", sa.UUID, nullable=False),
        # column whose name conveys its meaning — no comment needed
        sa.Column("joined_at", sa.DateTime(timezone=True)),
        # column that needs explanation
        sa.Column("role", sa.String(32), nullable=False),
    )
    op.execute(
        "COMMENT ON TABLE circle_memberships IS "
        "'Associates a user with a circle and their role in it.'"
    )
    op.execute(
        "COMMENT ON COLUMN circle_memberships.role IS "
        "'Member role: owner, editor, or viewer.'"
    )
```

Do not add a comment if the name is self-explanatory (e.g.
`created_at`, `email`, `id`). Do add a comment when:

- The column stores a code or enum value.
- The column has non-obvious business meaning.
- The table name alone does not describe its purpose clearly.

## Query conventions

- Use SQLAlchemy 2.x `select()` style. Do not use the legacy
  `session.query()` API.
- Keep queries in a `services/` or `repositories/` layer; route
  handlers must not contain raw SQL or `select()` calls.
- Use `RETURNING` clauses (via SQLAlchemy's `returning()`) to
  avoid a second round-trip after INSERT.

---

## Prohibited patterns

- `Base.metadata.create_all()` anywhere in application code.
- `session.query(Model).filter(...)` — legacy API.
- Raw SQL strings with string interpolation — use bound parameters.
- Connection strings in source code.
- Module-level `Session` instances.
- Creating indexes without naming them explicitly:

  ```python
  # BAD — Alembic generates an ugly hash name
  Index(None, User.email)

  # GOOD — explicit, referenceable name
  Index("ix_users_email", User.email, unique=True)
  ```

## Testing

```
uv add --dev pytest-asyncio sqlalchemy[asyncio] aiosqlite
```

Use an in-memory SQLite database for unit tests (SQLite compatible
models) or a separate PostgreSQL test database for integration
tests.

```python
# tests/conftest.py
import pytest
from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
from app.database import Base, get_db
from app.main import app

@pytest.fixture()
def db_session():
    engine = create_engine("sqlite:///:memory:")
    Base.metadata.create_all(engine)  # OK in tests only
    Session = sessionmaker(bind=engine)
    session = Session()
    try:
        yield session
    finally:
        session.close()
        Base.metadata.drop_all(engine)

@pytest.fixture()
def client(db_session):
    app.dependency_overrides[get_db] = lambda: db_session
    from fastapi.testclient import TestClient
    return TestClient(app)
```

`Base.metadata.create_all()` is **only** permitted in test
fixtures. It is never permitted in application code.
